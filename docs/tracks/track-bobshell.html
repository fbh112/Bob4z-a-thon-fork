Exercise 1 — Install & Start Bob Shell

Install Bob Shell, authenticate with your IBMid, and start your first interactive session from the CBSA workspace.

Step 1 — Install Bob Shell

Option A — Installation script (recommended):

# macOS / Linux
curl -fsSL https://bob.ibm.com/download/bobshell.sh | bash
# Windows (PowerShell)
powershell -ep Bypass 'irm -Uri "https://bob.ibm.com/download/bobshell.ps1" | iex'

Option B — from downloaded package:

npm install --reg=https://registry.npmjs.org/ -g "<file-path>"

Verify the installation:

which bob
bob --version

Step 2 — Start an interactive session

# Navigate to your CBSA workspace root
cd ~/CBSA/CBSA-base-source

# Start an interactive session
bob chat
⚠️ When Bob Shell runs from a project directory for the first time, a trust dialog appears — select Trust folder to avoid restricted safe mode.

Step 3 — Explore Bob Shell commands

Before running any task, explore what Bob Shell offers:

/

Opens the slash command menu. Other useful commands:

/help
/mode
/settings
/team
Bob Shell supports three modes: Agent (generate & modify code), Ask (read-only Q&A), Plan (reason before implementing). Switch with /mode.

Exercise 2 — Interactive Session: Exploring a Mainframe Project

Use Bob Shell in Ask mode to progressively explore the CBSA project: initialize the workspace, get a high-level overview, drill into a specific program, trace dependencies, then switch to Plan mode to design a change.

Type /mode and select Ask before starting.

Step 0 — Initialize the workspace

/init
Always run /init first in a new session — it seeds Bob Shell with full workspace context so subsequent prompts have accurate file and structure information.

Step 1 — Get a high-level project overview

Give me a high-level overview of this project: what languages are used, what are the key directories, and what does this application do?
Output:
· structured summary of languages detected (COBOL, BMS, JCL) and directory layout
· AGENTS.md — created at workspace root
· .bob/rules-agent/AGENTS.md, .bob/rules-ask/AGENTS.md, .bob/rules-plan/AGENTS.md — mode-specific rules files

Step 2 — Understand a specific program

@cobol_src/BANKDATA.cbl — explain this program: what is its purpose, what data structures does it define, and what are the key paragraphs in the PROCEDURE DIVISION?
Output:
· explanation of BANKDATA's role as a batch data loader
· key WORKING-STORAGE data structures (account and customer records)
· list of PROCEDURE DIVISION paragraphs with a one-line description of each

Step 3 — Trace dependencies across the project

Which copybooks does @cobol_src/BANKDATA.cbl include, and which other programs in cobol_src/ also use those same copybooks?
Output:
· list of copybooks used by BANKDATA (e.g., CUSTOMER.cpy, SORTCODE.cpy)
· cross-reference of other programs that include each copybook — showing the full change impact boundary

Step 4 — Switch to Plan mode and design a change

Type /mode, select Plan, then enter:

I need to add a new field EMAIL-ADDRESS (PIC X(100)) to the customer record in @CUSTOMER.cpy. What is the safest way to do this without breaking existing programs?
Output:
· add-email-address-plan.md — structured plan document saved in the current directory
Press Ctrl+C twice to exit the interactive session before moving to Exercise 3.

Exercise 3 — Non-Interactive Sessions: Automating Tasks

Use Bob Shell's non-interactive mode (bob run "...") to automate documentation generation from the command line — suitable for CI/CD pipelines.

⚠️ Before the first non-interactive use, set up your API key: create one at bob.ibm.com, then run: export BOB_API_KEY="your-api-key"

Option 1 — Single-file non-interactive example

bob run "Write a one-paragraph technical summary of @cobol_src/BANKDATA.cbl. Output only the summary text, no markdown formatting."

Option 2 — Batch documentation script

Save as gen-docs.sh:

#!/bin/bash
mkdir -p docs

for cbl in cobol_src/*.cbl; do
  program=$(basename "$cbl" .cbl)
  echo "Documenting $program..."
  bob run "Write a one-paragraph technical summary of @${cbl}. Output only the summary text." \
    > "docs/${program}-summary.txt"
done

echo "Documentation complete. Output in docs/"
chmod +x gen-docs.sh
./gen-docs.sh
Output:
· docs/ folder populated with .txt summary files — one per COBOL program — each containing a technical description of the program's purpose, inputs, and outputs

Option 3 — Pipe a prompt from a file

echo "list current file structure" >> prompt.txt
cat prompt.txt | bob
Output:
· the current file structure of the workspace displayed in the terminal
The bob run pattern can be embedded in CI/CD pipelines (GitHub Actions, Jenkins, etc.) for automated code documentation and quality checks on every commit.
